## 已经核过的边界

- **工具栏**：按仓库所有者确认保留 9 + 6 + 4 + 1，共 20 个可操作按钮；翻译和语种下拉分别计数。实际离屏布局测过 1280×720 在 100%、125%、150%、200% 的等效 DIP，以及 920×680 @ 200%：组内不拆，不把按钮收进菜单。
- **设置**：真实窗口测过 920×620 和最小 820×560。旧的 45 帧组合显示自定义，不会因为打开页面而改成 30 帧。连接状态使用隔离凭据和模拟 HTTP 验证，覆盖成功、回退、失败，以及正在测试时更换配置。Windows 11 26200 上实际 HWND 的 DWM 属性 20 / 38 读回为 1 / 2。
- **GIF**：随附 FFmpeg 由固定源码重新编译。验证过完整导出、裁剪、缩小 / 不缩放、循环、极短和稀疏帧素材；测试不仅看帧数和总时长，还逐帧核对最后一次变色。实际预览的文件拷贝在隔离的 Windows 窗口站往返成功，关闭预览后路径可用，取消导出原 MP4 哈希不变。旧包会明确提示更新。本机 RTX 4060 的 NVENC 编码和 D3D11VA 解码均通过。
- **浮层开销**：同机同夹具，3840×2160 合成输入、实际离屏窗口 3840×1102。P0 预热 7 次中位 88.3 ms，P9 抽测 86.8 ms（82.1–116.0 ms）（只含构造至首次布局，不含热键、DXGI 与首次合成）。单独生成 4K 模糊图预热 8.7–12.7 ms；首次含线程 / JIT / WPF 初始化为 76.9 ms，UI 不等待它。
- **释放**：分别反复完成模糊后关闭和立即关闭；扩展到每组 70 次，窗口和已分发模糊图均无托管弱引用残留。进程私有内存仍有缓慢波动，P0 对照也有，不能据此断言原生内存长期恒定。

## 与方案文字有差别的地方

- 工具栏采用已确认的 **20 个**实际操作。小面板与成功提示采用硬性约束的 6 档常规圆角；开关、色点和倒计时等本来就是圆形的元素除外。
- 录制格式是设置条与控制条的共同输入，因此先在 P5 引入格式枚举和默认字段；GIF 参数、编码、文件交付与重编仍属于 P6。P1 遵守「只改 Tokens.xaml」，全局样式在 P2 接入，README 在 P9 更新。
- GIF 裁剪先保留定位点之前仍在显示的画面，再按目标帧率截取应有帧数，最后才生成调色板。输入端直接用示例的 `-to` 会截短可变帧率录屏。固定 FFmpeg 的差分直方图另外有[一行修正](../../../tools/ffmpeg/palettegen-diff-current-frame.patch)，避免漏掉最后一次变色；仍用差分调色板、Bayer 抖动、无限循环，不使用低质量替代编码。
- 保留了原来的四档文字字号、三种字重、三档序号尺寸、放大倍率与 RGB/HEX 切换、主翻译失败时的回退原因、录制边框上的尺寸提示，以及单独的光标 / 点击效果默认值。预览中的音量改用可拖动和键盘调节的滑杆，四档倍速未减少。
- 结束录制沿用预览窗；未额外再弹录屏缩略图。未启用可选的录制边框全屏循环外发光，以减少多屏持续合成。成功拷贝**截图**的缩略图不受此取舍影响。
- 本地 HTML 原型的 `file:` 地址未获受控 Edge 放行；对照的是方案和原型「优化后」的样式、结构与交互源码，并非一次浏览器实看验收。两张弹出菜单图取自实际 WPF 弹层，按目标窗口相对位置合成，不用于证明系统最终落点。

## 仍需人工实机验收

| 环境 / 操作 | 应看到什么 |
| --- | --- |
| 多显示器、负坐标、主副屏互换、旋转屏；从录屏热键跨屏框选 | 选区、放大镜物理坐标和视频边界对齐。控制条避开录制区域；复制成功缩略图落在选区所在显示器工作区，且不抢焦点。 |
| 100 / 125 / 150 / 200% 混合 DPI，拖设置窗跨屏；小选区靠四角 | 菜单不被截断；工具栏只按组换行；玻璃背景在缩放、移动后仍从正确位置取样。最小设置窗内每个字段均可滚到并修改。 |
| Windows 10 21H2（19044）与更新系统；Windows 11 关闭透明效果或开启高对比度 | Win10 设置为纯色，不要求 Mica；支持条件满足的 Win11 使用 Mica。关闭透明效果后界面仍清晰；截图玻璃不依赖系统模糊。 |

| GIF 的 10 / 15 / 20 / 30 fps、原始 / 1920 / 1280 / 960 宽度；录静止画面再切色或移动指针 | 实际播放器循环正常、末段颜色不丢。中间裁一段，分别另存和粘贴到目标聊天应用 / 资源管理器；关闭预览后仍能使用。长片取消、空间不足或移除 GIF 能力时，原 MP4 可恢复。 |
